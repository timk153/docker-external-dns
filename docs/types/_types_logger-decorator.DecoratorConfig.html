  • OptionalclassProperties?: boolean

    if set to true, class-properties will also be logged (applied to class decorators only). https://babeljs.io/docs/en/babel-plugin-proposal-class-properties

  • OptionalcontextSanitizer?: Sanitizer

    function to sanitize function context. function context is an optional parameter supplied to the decorator for the function being logged.

    simpleSanitiser can be used. writes out using util.inspect for Node: htps://nodejs.org/api/util.html#util_util_inspect_object_options

    dataSanitiser can also be used. dataSanitiser looks for anything matching the regular expression /password/ and replace it with ***

    Recommended to write your own for your specific use case.

    IMPORTANT, no default, if ommited no context is written out.

    Param: data

    Data being logged out

    Returns

    Sanitized data for logging (array if input is array else string)

  • Optionalduplicates?: boolean

    if set to true, it is possible to use multiple decorators at once. Default is false

  • OptionalerrorLevel?: LogLevel

    the level used for errors; 'error' by default. Also, a function could be passed. The function will receive logged data and should return the log-level as a string.

  • OptionalerrorSanitizer?: Sanitizer

    function to sanitize errors for logging.

    simpleSanitiser can be used and is use by default. writes out using util.inspect for Node: htps://nodejs.org/api/util.html#util_util_inspect_object_options

    dataSanitiser can also be used. dataSanitiser looks for anything matching the regular expression /password/ and replace it with ***

    Recommended to write your own for your specific use case.

    Param: data

    Data being logged out

    Returns

    Sanitized data for logging (array if input is array else string)

  • OptionalerrorsOnly?: boolean

    if set to true, the logger will catch only errors. default is false.

  • Optionalexclude?: string[]

    array with method names for which logs won't be added.

  • Optionalgetters?: boolean

    if set to true, getters will also be logged (applied to class and class-method decorators). https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Functions/get

  • Optionalinclude?: string[]

    array with method names for which logs will be added.

  • OptionalkeepReflectMetadata?: string[]

    if logger-decorator is used with other decorators, they can set own reflect metadata. By passing keepReflectMetadata array, you can prevent metadata from resetting. For example, for NestJS, it's a good idea to use { keepReflectMetadata: ['method', 'path'] }.

  • Optionallevel?: LogLevel

    the default log-level; pay attention that the logger must support it as logger.level(smth), 'info' by default. Also, a function could be passed. The function will receive logged data and should return the log-level as a string.

  • OptionallogErrors?: { deepest?: boolean }

    Child options available

    • Optionaldeepest?: boolean

      log only th;e deepest occurrence of the error. This option prevents 'error spam.' Default is false

  • OptionalmethodNameFilter?: (name: string) => boolean

    function to filter method names. default omits constructor but logs everything else.

  • OptionalparamsLevel?: LogLevel

    the level used for logging params. Logger will print input params before the function starts executing. Also, a function could be passed. The function will receive logged data and should return the log-level as a string. If omitted, nothing will be logged before execution.

  • OptionalparamsSanitizer?: Sanitizer

    dataSanitiser can also be used and is set by default. dataSanitiser looks for anything matching the regular expression /password/ and replace it with ***

    Recommended to write your own for your specific use case.
